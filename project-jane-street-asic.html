Programmable Protocol Emulator ASIC — Jane Street Challenge

A small processor that turns wire protocols into firmware. Instead of committing the chip to one UART, SPI, or I²C circuit, one deterministic execution engine can change behavior through a serial program loader after reset.

View source Competition brief

Overview

The challenge is to build a general-purpose protocol emulator, not three unrelated protocol blocks. This design moves the protocol sequence into a short program: instructions choose pin values and directions, wait exact cycle counts, sample inputs, perform small integer operations, and branch.

  • Builder: Dhruva Uppaluri.
  • Current status: RTL, protocol firmware, regression tests, lint, and generic synthesis pass.
  • Core: 32 × 16-bit program memory, four 8-bit registers, eight bidirectional pins, and a 16-instruction ISA.
  • Extension: a tiny programmable linear classifier for short patterns in protocol-pin activity.
  • Remaining: physical IHP placement, routing, extracted timing, DRC/LVS, and tapeout sign-off.

Independent project: this work responds to the public competition brief and is not affiliated with or endorsed by Jane Street.

System architecture

The silicon remains fixed while firmware changes its behavior. A serial configuration interface writes words into the instruction memory, then releases the core to execute from address zero.

serial configuration input
          │
          ▼
  program loader ──► 32 × 16 program memory
                              │
                              ▼
                     protocol processor ──► 8 bidirectional pins
                              ▲                       │
                              └── status / result ◄── classifier

The same fabricated chip can transmit a UART byte, generate an SPI transaction, detect an I²C START/STOP condition, or run a future protocol program without changing the RTL.

The 16-instruction machine

Each instruction is 16 bits: a 4-bit opcode identifies the operation and the remaining 12 bits carry operands such as a register number, pin mask, delay, or branch address.

GroupInstructionsPurpose
Pin and timingOUT, DIR, WAIT, WAIT_PINDrive pins, choose direction, and control exact timing.
Input and dataIN, LDI, ANDI, XORI, ADDI, SHL, SHRSample pins and transform small values.
Control flowJMP, JZ, JNZ, NOP, HALTRepeat, branch, and stop protocol programs.

The processor advances one instruction at a time unless an instruction intentionally stalls it. Firmware can count clock cycles instead of relying on a scheduler or interrupt latency.

Protocol firmware

The repository includes an assembler and working examples that all execute on the same processor:

  • UART: transmit 0xA5 as an 8N1 frame at 1 Mbit/s from a 50 MHz clock.
  • SPI: generate a mode-0 nibble transfer with explicit clock and data timing.
  • I²C: produce and detect START/STOP behavior through open-drain-style pin direction control.

Tiny signal classifier

This is a small ML-inspired extension, not a general AI accelerator. Over a 32-cycle window it extracts four features—the transition and high-cycle counts of pins 0 and 1—then computes a signed linear score from four INT8 weights and a signed 16-bit bias. One time-multiplexed multiplier keeps the hardware compact.

score = bias + w₀x₀ + w₁x₁ + w₂x₂ + w₃x₃
class = 1 when score ≥ 0

Firmware can read the result through processor input bit 7 and branch on it. This lets the protocol engine react to a learned threshold over signal behavior while keeping every parameter programmable.

Verification and synthesis

  • Self-checking processor tests exercise all 16 opcodes, branches, deterministic waits, pin direction, sampling, and halt behavior.
  • Firmware-level tests validate the UART, SPI, and I²C programs through the integrated processor.
  • Classifier tests cover feature capture, signed arithmetic, programmable parameters, and the CPU-visible result.
  • Verilator lint and the complete RTL regression pass in GitHub Actions.
  • Yosys completes generic synthesis at approximately 3,088 cells before technology mapping.

What this proves: the logical design and its tests are working. It does not yet prove routed timing, DRC/LVS cleanliness, or tapeout readiness.

FPGA precursor

Before the full processor, two smaller timing blocks were fitted for an Intel Cyclone V 5CSEMA5F31C6 in Quartus Prime Lite 25.1. Both passed setup and hold timing against a 10 ns clock constraint at the slow 1100 mV, 85 °C corner.

These results established the timing model; the current programmable ASIC RTL is a later and substantially larger design.

What comes next

The RTL is intentionally staying stable while the FPGA research continues separately. When this project returns to the tapeout track, the next work is technology mapping into the official IHP flow, floorplanning, placement and routing, extracted timing, DRC/LVS, and gate-level verification.

Keeping that distinction visible matters: “RTL complete” means the programmed behavior is implemented and verified, while “tapeout ready” requires a second physical-design proof.
