Jane Street ASIC & Malleable FPGA AI System

A modular FPGA architecture that combines a deterministic protocol processor with a configurable neural-network accelerator—and eventually adapts that hardware to each AI model automatically.

View source Competition brief

Overview

The project began with a protocol-emulator processor in response to Jane Street’s ASIC competition and is growing into a broader FPGA research system. One modular processor handles control, communication, and deterministic timing; a separate accelerator performs neural-network computation.

  • Builder: Dhruva Uppaluri.
  • Current milestone: complete the first SET/WAIT/HALT protocol processor.
  • Verification: self-checking simulations run locally and in GitHub Actions.
  • Research goal: automatically select an efficient accelerator configuration for an AI model and a target FPGA.

Research question: can an FPGA act as a malleable AI compute platform whose architecture is adapted to the workload instead of building one fixed accelerator for one model?

Independent project: this work responds to the public competition brief and is not affiliated with or endorsed by Jane Street.

Target architecture

The processor and accelerator remain separate, independently testable blocks connected by a small internal bus. The processor coordinates data and peripherals; the accelerator stays outside the processor datapath and concentrates on multiply-accumulate workloads.

SubsystemResponsibilityPlanned structure
Protocol processorControl, exact timing, communication, and data movementProgram counter, instruction memory, decoder, registers, and timer
Protocol I/OCommunicate with external hardwareProgrammable UART, SPI, I²C, and GPIO behavior
AI acceleratorExecute expensive neural-network operationsMAC array, weight and activation buffers, configurable datapath, and controller
Software optimizerMatch hardware to the model and available FPGA resourcesModel analyzer, configuration search, build automation, and measured feedback

The processor will eventually access the accelerator through registers such as control, input, weight, status, and result. A normal transaction is: supply data, issue START, wait for DONE, then read the result.

What works today

Programmable timing core

The pin generator accepts a runtime timing value, toggles after the requested number of enabled clock edges, and preserves its count while paused. Its testbench checks five-cycle and three-cycle timing, a four-clock pause followed by exact continuation, and a safe idle-low output when the timing value is zero.

UART reference implementation

The UART transmitter sends 8N1 frames least-significant bit first. At a 100 MHz input clock it uses 100 clocks per bit for a 1 Mbit/s data rate, latches each byte at the start, keeps busy asserted through the frame, and pulses done afterward. The self-check verifies complete frames for 0x55 and 0xA3.

First instruction ROM

A verified 16-bit program ROM now encodes the first SET, WAIT, and HALT sequence. The next integration step is to connect it to a program counter, decoder, exact-cycle wait timer, GPIO register, and persistent halt state.

Implementation results

Quartus Prime Lite 25.1 compiled and fitted both blocks for an Intel Cyclone V 5CSEMA5F31C6. Both pass setup and hold timing against a 10 ns clock constraint at the slow 1100 mV, 85 °C corner.

The first versions will choose among configurable accelerator parameters. More substantial FPGA reconfiguration is a later research step, only after the baseline accelerator and optimizer work reliably.

Current focus

The immediate priority remains the protocol processor—not the AI hardware. The timing foundation, fixed UART reference, and first instruction ROM are verified. Next comes the integrated processor, followed by a UART program that must match the fixed transmitter cycle for cycle.

Each major block will be developed as a small, measurable milestone with RTL, a self-checking testbench, simulation, synthesis, resource utilization, and timing results before the system grows more complex.
