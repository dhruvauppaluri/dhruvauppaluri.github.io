Jane Street Protocol Emulator ASIC

A programmable hardware engine for reproducing UART, SPI, I²C, and other digital protocols with exact cycle timing.

View source Competition brief

Overview

We are building an open-source, cycle-accurate protocol emulator in response to Jane Street’s protocol emulator ASIC competition. The target is a small programmable processor that can read pins, write pins, and wait an exact number of clock cycles, allowing several protocols to run on the same hardware engine.

  • Builders: Dhruva Uppaluri and Anishkumar Senthil.
  • Current milestone: verified programmable timing and a fixed 1 Mbit/s UART transmitter.
  • Verification: self-checking simulations run locally and in GitHub Actions.
  • Hardware result: both completed RTL blocks fit and close timing at 100 MHz on a Cyclone V FPGA.

Independent project: this work responds to the public competition brief and is not affiliated with or endorsed by Jane Street.

What works today

Programmable timing core

The pin generator accepts a runtime timing value, toggles after the requested number of enabled clock edges, and preserves its count while paused. Its testbench checks five-cycle and three-cycle timing, a four-clock pause followed by exact continuation, and a safe idle-low output when the timing value is zero.

UART reference implementation

The UART transmitter sends 8N1 frames least-significant bit first. At a 100 MHz input clock it uses 100 clocks per bit for a 1 Mbit/s data rate, latches each byte at the start, keeps busy asserted through the frame, and pulses done afterward. The self-check verifies complete frames for 0x55 and 0xA3.

Implementation results

Quartus Prime Lite 25.1 compiled and fitted both blocks for an Intel Cyclone V 5CSEMA5F31C6. Both pass setup and hold timing against a 10 ns clock constraint at the slow 1100 mV, 85 °C corner.

Main challenge

A protocol emulator must be flexible without sacrificing deterministic timing. A conventional processor can vary in how long an operation takes, while this engine must drive or sample a pin on a precisely defined clock edge. That makes the timer, instruction format, pause behavior, and invalid inputs part of the hardware contract.

We are handling that risk by verifying small blocks independently before connecting them. Each milestone has a self-checking testbench, and continuous integration reruns those tests on every push.

Current status and next steps

The timing foundation and UART reference block are verified. The next major step is the programmable execution engine: define the first SET, WAIT, and HALT instructions, then connect instruction memory, a program counter, and a decoder.

After UART can run as a program, the roadmap adds pin sampling and conditional branches, demonstrates SPI and I²C on the same engine, and ports the design to the Tiny Tapeout IHP 130 nm CMOS flow.
