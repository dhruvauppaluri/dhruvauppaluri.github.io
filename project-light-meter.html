DIY Light Meter — Film & Mirrorless Cameras

A handheld light meter built from discrete components that outputs aperture, ISO, and shutter combinations for film SLRs and mirrorless bodies in real time.

Project Overview

  • Role: Solo project
  • Key hardware: Arduino UNO, LDR + 10KΩ divider, LCD1602, rotary encoder (CLK/DT/SW), contrast potentiometer, breadboard
  • Tools used: Arduino IDE (C++/AVR), serial monitor (9600 baud debug), reference light meter app for calibration

The Challenge

Shooting fully manual with a manual lens means setting aperture, ISO, and shutter speed yourself with no in-lens communication to the camera body. In-camera meters are easy to misread off bright or dark subjects. A small dedicated light meter gives you a separate exposure readout while you dial settings on the body. Good handheld meters are often expensive; this one was built from scratch around an LDR, an Arduino, and a simple UI.

Requirements

  • Lux to exposure: convert sensed illuminance into standard photographic EV and match to standard shutter speeds on a log scale.
  • Film / SLR mode: user sets aperture and roll ISO; device outputs the correct shutter speed, with encoder-driven UI to edit aperture vs ISO.
  • Mirrorless mode: user sets aperture only; firmware walks ISO upward until shutter speed meets a hand-hold threshold (≥ 1/60s), similar to Auto-ISO on a digital body.
  • Responsive UI: rotary encoder must register every detent — no blocking delay() that skips pulses.
  • Field calibration: uncalibrated LDR scaled by firmware constant CAL, tuned against a reference meter across multiple lighting conditions.

Design & Logic

Light sensing

An LDR (light-dependent resistor) sits in a voltage divider with a 10KΩ resistor. The Arduino reads the junction voltage on an analog input (A0) and converts it to an approximate lux value using the LDR's resistance curve.

Exposure value formula

The meter implements the standard photographic EV formula:

EV₁₀₀ = log₂(lux / 2.5)

Where EV100 is the exposure value calibrated to ISO 100. From there, shutter speed is solved algebraically: 

t = N² / 2^(EV₁₀₀ + log₂(ISO / 100))

Where N is the f-number (aperture) and t is shutter speed in seconds. The result is matched to the nearest standard shutter speed on a log scale.

Two metering modes

Film / SLR mode

  • The user sets aperture and film ISO (locked per roll). The meter outputs the correct shutter speed.
  • A short click on the rotary encoder toggles the cursor between aperture and ISO selection.

Mirrorless mode

  • The user sets aperture only.
  • The meter walks the ISO ladder from 100 upward, solving for shutter speed at each step, and outputs the lowest ISO that produces a hand-holdable shutter speed (≥ 1/60s).
  • This mirrors how a camera's Auto-ISO logic works internally.

Calibration

The photoresistor is not factory-calibrated. A scalar calibration constant (CAL) in firmware scales the lux output. Calibration was performed by comparing meter output against a reference light meter app across multiple lighting conditions (indoor tungsten, shade, overcast, direct sun) and adjusting CAL until readings agreed within one-third stop.

Firmware architecture

  • Written in C++ for Arduino (AVR)
  • Fully non-blocking main loop — no delay() calls
  • Encoder read on every loop iteration (falling-edge detection) for zero missed pulses
  • LCD and LDR updates on independent millisecond timers (120ms / 100ms)
  • Short click vs long press detection on encoder SW for dual-function button
  • Serial debug output streams ADC, lux, EV, ISO, and shutter speed at 9600 baud

Debugging & Iteration

  • The problem: The encoder direction appeared stuck — it only stepped one way.
  • Why it broke: Arduino UNO pin 13 has a built-in LED and series resistor tied to ground, so ENC_DT could not float HIGH correctly and the direction bit was wrong.
  • The fix: Moved DT to pin 12.
  • Result: Reliable clockwise/counterclockwise decoding.
  • The problem: The UI felt laggy and the encoder skipped detents.
  • Why it broke: A delay(150) in the main loop limited polling to ~6 Hz, so most mechanical steps happened between samples.
  • The fix: Removed all blocking delays; poll the encoder every loop iteration (~10k iter/s) and refresh LCD/LDR on separate millis timers.
  • Result: Immediate, repeatable encoder response.
  • The problem: Occasional false or double steps on cheap encoder edges.
  • Why it broke: Noisy transitions on both edges of CLK.
  • The fix: Count only the falling edge of CLK for each detent.
  • Result: Fewer spurious toggles; one detent maps to one UI step.
  • The problem: Calibrating lux from an uncharacterized LDR.
  • Why it broke: Film mode fixes ISO, so lux error shows up directly as shutter error; mirrorless mode can mask bias by bumping ISO to hit the 1/60s floor.
  • The fix: Tune scalar CAL against a reference meter across scenes; use the film vs mirrorless asymmetry to spot offset.
  • Result: Readings within about one-third stop of the reference app across tungsten, shade, overcast, and sun.

Wiring discipline matters too: keep analog sensor leads short and avoid routing sensitive lines next to noisy digital edges where possible on a breadboard build.

Reflection

  • Analog front end: voltage divider + ADC is simple, but the LDR curve and CAL dominate absolute accuracy — mirrorless mode's Auto-ISO behavior changes how errors appear.
  • What I learned: Non-blocking structure is not optional for mechanical encoders; pin choice on Arduino (e.g. pin 13) is part of the schematic, not just firmware.
  • Exposure math: Implementing log-scale EV and standard shutter snapping in firmware reinforced how cameras expose under the hood.
  • Skills: ADC and divider design, embedded C++ state machine, hardware debug (pin conflict, signal integrity), reference-based calibration.
  • Next iteration: enclosure-ready PCB in KiCAD; BH1750 for factory-calibrated lux; ±1 stop bracketing on LCD; 3D-printed or laser-cut enclosure with optional diffusion dome over the sensor.

Final Result & Validation

  • Computed EV drives correct shutter for user-set aperture/ISO (film) or Auto-ISO-style behavior to ≥ 1/60s (mirrorless).
  • A responsive meter depends as much on firmware architecture and pin-level hardware awareness as on the exposure equations.
