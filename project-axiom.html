Axiom

Open-source stack to drive a four-motor robot over USB or BLE: Arduino firmware, a Python daemon, a browser UI, and serial tools for hardware bring-up.

github.com/dhruvauppaluri/axiom

Project Overview

  • Role: solo project
  • Key hardware: Arduino Uno, four-motor H-bridge drive, SG90-style servo, HC-SR04 ultrasonic, HM-10 BLE module
  • Stack: robot_car.ino firmware, rc_daemon.py (BLE + USB + WebSocket), browser control UI, probe.ino for circuit bring-up
  • Repository: github.com/dhruvauppaluri/axiom

Objective

I wanted one place to drive a robot from my laptop or phone — same commands whether the Arduino is on USB at the desk or on BLE across the room. Axiom is that repo: line-oriented firmware on the Uno, a host daemon that owns both links and exposes WebSocket to a browser, plus a separate probe sketch for when the motors do not move and you need to know if the problem is code or copper.

System architecture

  • Firmware (firmware/robot_car/): text commands over USB serial and HM-10 BLE — forward, tank turn, per-motor PWM, servo angle, ultrasonic distance, motor identify sweep.
  • Host daemon (control/rc_daemon.py): one process owns BLE and USB, exposes a WebSocket API on port 8766, reconnects when links drop, fans telemetry out to clients.
  • Web UI (control/index.html): D-pad driving, cruise speed, servo slider, live distance readout, connection status for BLE vs USB.
  • Probe (probe/probe.ino): serial bench tool — pin voltage reads, continuity checks, motor-pin scan when a transistor stage is miswired.
  • BLE passthrough (firmware/bt_passthrough/): minimal bridge for debugging the radio link before the full robot sketch is loaded.

Implementation

Robot firmware

Four PWM motor channels on a differential layout, software servo timing, and ultrasonic ranging on shared digital pins. Commands are line-oriented and identical whether they arrive on USB or BLE. Motor outputs are forced LOW at boot with direct port writes so the car does not jerk on reset — small detail, but it mattered when I was debugging drivers hot enough to smell wrong.

Control daemon

Python asyncio ties together Bleak for GATT writes to the HM-10, pyserial for the Arduino USB path, and websockets for the browser. The daemon scans for known BLE names, clears stale macOS Bluetooth pairings when the module disappears, and broadcasts serial responses to every connected UI client.

Web interface

A single-page controller that talks to the daemon over WebSocket — no native app required. Connection state is visible at a glance (BLE only, USB only, both, or scanning) so I know whether a failed command is a UI bug or a dead link.

Debugging & iteration

  • I did not trust the motor wiring until I could prove which pin was actually switching — that is what probe.ino is for.
  • Cause: a bad solder joint or wrong transistor leg looks like “firmware is broken” until you read the node with a jumper and see 0 V when you expected 5 V.
  • Fix: live voltage commands, per-pin drive tests, and a SCAN mode that walks the motor outputs while reporting analog readings.
  • Outcome: separate “is the circuit alive” from “is the protocol wrong” before I spend an hour in the daemon logs.

BLE added its own class of problems — stale connections on macOS, modules that need a power cycle, and the difference between seeing the radio in a scan and actually getting a READY back from firmware. The daemon retries with backoff and can bounce Bluetooth through blueutil when the link ghosts.

Reflection

Axiom is the glue between “I flashed the Arduino” and “I can actually drive this thing from a UI.” Most of the repo is unglamorous: parsing text commands, reconnecting BLE when macOS ghosts the pairing, and a probe sketch because transistor stages lie.

What I would do next is tighten the protocol (fewer ad-hoc single-letter commands), add proper docs in the repo, and harden the daemon for long sessions. The architecture — firmware, daemon, web client — is the part I am happy to reuse on other robots without rewriting from scratch.

Repository

Source, firmware, and the web UI live in the open repo: github.com/dhruvauppaluri/axiom. Clone control/rc_daemon.py, flash firmware/robot_car/robot_car.ino, open control/index.html while the daemon is running.
