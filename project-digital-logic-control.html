Virtual EV Transmission — Discrete Logic Gearbox

A hardware-only gearbox controller that cycles through four gear states using nothing but 74-series logic chips. No microcontroller, no firmware.

Project Overview

  • Role: solo project
  • Key hardware: 74LS74 (dual D flip-flops), 74LS86 (quad XOR gates), 74HC14 (Schmitt-trigger inverters)
  • Tools used: KiCAD, breadboard prototyping, DMM measurements, Arduino for power/GND supplies during testing

The Challenge

I wanted to learn how logic gates and ICs can carry binary information through a circuit, and how that learning connects to PCB design and real-world implementation. That motivation grew when I saw Mazda release a fully EV car with electronic gear shifts, and I wanted to replicate the concept using only discrete IC logic (no microcontroller programming).

When I saw Mazda release a fully electric car with electronic gear shifts, I wanted to understand how gear state could be managed at the hardware level, before any software gets involved. The constraint I set for myself was strict: no microcontroller, no firmware, no shortcuts. Every transition had to be decided by gates.

This first iteration handles Shift Up. Each press advances the state one step through a four-gear cycle: 00 to 01 to 10 to 11 and back to 00. Shift Down comes next.

Requirements

I needed three things to be true. The state had to update synchronously, meaning the flip-flops could only change on a clean clock edge, not whenever the input happened to change. The shift button had to produce exactly one clock per press regardless of how bouncy the mechanical contact was. And all of the transition logic had to live in discrete gates, not code. That last constraint was the point of the whole project.

Design & Logic

Logic Theory

I derived the excitation/next-state mapping for a 2-bit gearbox state machine. The XOR-based combinational network determines whether the state should toggle on the next synchronous update, while the 74LS74 flip-flops hold the gear state.

Shift Up state flow (cyclic): 00 -> 01 -> 10 -> 11 -> 00.

Visual feedback uses three LEDs: LED1 indicates the manual shift button/actuation state, while LED2 and LED3 represent the current 2-bit gear state (00 to 11).

Implementation

Prototype Phase

Component Selection

The 74LS74 holds the state. Two D flip-flops that only update on a rising clock edge, which is what makes the behavior synchronous. The 74LS86 is the decision layer — a quad XOR gate network that figures out whether each flip-flop should toggle on the next clock based on the current state. The 74HC14 is what made everything else work. Its Schmitt-trigger inputs use hysteresis to convert a bouncy mechanical switch edge into a clean transition the flip-flops can actually trust. Without it, one physical press looked like several clocks.

Signal Conditioning

A mechanical button does not produce a clean on-off transition. It bounces. The contacts make and break several times in a few milliseconds before settling. To synchronous logic, each bounce looks like a separate clock edge. The 74HC14 uses hysteresis to ignore the noise and output one clean edge per press. That single component is what made the difference between a state machine that worked and one that jumped unpredictably.

Debugging & Iteration

  • I did not know switch bounce was a thing until this project showed me what it looks like in hardware.
  • Cause: the 74LS74 flip-flops treated each micro-bounce as a clock, making the gear state jump unpredictably.
  • Fix: routed the shift input through the 74HC14 Schmitt-trigger inverter to use hysteresis and clean the signal before it reached the flip-flops.
  • Outcome: one physical press now produces one reliable clock command, so transitions are stable and repeatable.

Wiring discipline also matters for synchronous logic: keeping XOR-to-flip-flop connections organized helps preserve clean logic levels during clocked updates on the breadboard.

Reflection

What I did not expect was how much wiring layout affects behavior on a breadboard. Long runs between the XOR gates and the flip-flop clock pins pick up enough noise to cause phantom transitions. Keeping those connections short and organized was not an aesthetic choice, it was a functional one. I had to break it first to learn that.

The next version adds Shift Down, which means working out the down-transition excitation mapping and adding the missing logic to the XOR network. The hardware side is mostly done. The state machine just needs to go both directions.

Final Result & Validation

The video shows one press, one gear change, every time. That was the goal. Shift Down is next.
