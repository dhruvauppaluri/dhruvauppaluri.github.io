DIY Incident Light Meter — Film & Digital Mode

A handheld incident light meter built from discrete components that outputs correct exposure settings for both film SLR and digital cameras in real time.

Photo

Hardware photo coming soon.

The problem

Shooting fully manual with a manual lens means setting aperture, ISO, and shutter speed yourself with no in-lens communication to the camera body. Built-in camera meters measure reflected light, which can be fooled by bright or dark subjects. A dedicated incident meter reads the light falling on the scene — the same method professional photographers use for accurate exposure. Commercial incident meters cost $200–$500. This one was built from scratch.

How it works

Light sensing

An LDR (light-dependent resistor) sits in a voltage divider with a 10KΩ resistor. The Arduino reads the junction voltage on an analog input (A0) and converts it to an approximate lux value using the LDR's resistance curve.

Exposure value formula

The meter implements the standard photographic EV formula:

EV₁₀₀ = log₂(lux / 2.5)

Where EV100 is the exposure value calibrated to ISO 100. From there, shutter speed is solved algebraically: 

t = N² / 2^(EV₁₀₀ + log₂(ISO / 100))

Where N is the f-number (aperture) and t is shutter speed in seconds. The result is matched to the nearest standard shutter speed on a log scale.

Two metering modes

Film / SLR mode

  • The user sets aperture and film ISO (locked per roll). The meter outputs the correct shutter speed.
  • A short click on the rotary encoder toggles the cursor between aperture and ISO selection.

Digital mode

  • The user sets aperture only.
  • The meter walks the ISO ladder from 100 upward, solving for shutter speed at each step, and outputs the lowest ISO that produces a hand-holdable shutter speed (≥ 1/60s).
  • This mirrors how a camera's Auto-ISO logic works internally.

Calibration

The photoresistor is not factory-calibrated. A scalar calibration constant (CAL) in firmware scales the lux output. Calibration was performed by comparing meter output against a reference light meter app across multiple lighting conditions (indoor tungsten, shade, overcast, direct sun) and adjusting CAL until readings agreed within one-third stop.

Firmware architecture

  • Written in C++ for Arduino (AVR)
  • Fully non-blocking main loop — no delay() calls
  • Encoder read on every loop iteration (falling-edge detection) for zero missed pulses
  • LCD and LDR updates on independent millisecond timers (120ms / 100ms)
  • Short click vs long press detection on encoder SW for dual-function button
  • Serial debug output streams ADC, lux, EV, ISO, and shutter speed at 9600 baud

Key engineering decisions

Why falling-edge encoder detection?

Cheap rotary encoders produce noisy signals on both edges. Triggering only on the falling edge of CLK cuts false triggers in half and gives clean single-step increments per detent.

Why move ENC_DT off pin 13?

Arduino UNO pin 13 has a built-in LED and series resistor tied to ground. This prevents the pin from floating HIGH correctly, causing the direction signal to always read the same value — making the encoder appear to spin in one direction only. Moving DT to pin 12 resolved this immediately.

Why non-blocking loop?

A delay(150) in the original loop meant the encoder was only polled 6 times per second — missing most physical detents. Removing all delays and checking the encoder on every iteration (at ~10,000 iterations/sec) made the UI immediately responsive.

Why does digital mode hide calibration error?

Digital mode auto-selects ISO to hit a minimum shutter threshold. A 1-stop underestimate in the lux reading is absorbed by bumping ISO one step — shutter speed still outputs 1/60. Film mode exposes the error directly because ISO is fixed. This asymmetry was used to isolate and correct the calibration offset.
